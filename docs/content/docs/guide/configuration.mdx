---
title: Configuration
description: Where the Studio finds a site's pages, their files and its diagrams.
---

The Studio edits one project: a folder of a git repository, usually the
root of a fumadocs site. It reads `fdbook.config.ts` in that folder; without
one, it uses the defaults below.

```ts title="fdbook.config.ts"
import { defineConfig } from '@fdbook/studio/config';

export default defineConfig({
  root: 'content/docs',
  media: 'public/docs',
  diagrams: 'diagrams',
  baseUrl: '/docs',
});
```

Every path is relative to the config file and must stay inside the
repository. The names follow `StudioConfig` of `@fumadocs-editor/studio`
where they mean the same thing.

| Field | Default | What it is |
| --- | --- | --- |
| `root` | `content/docs`, else `content` | The pages: `.mdx` files and the `meta.yaml` files that order them. |
| `media` | `public/docs` | Where the Studio saves the files a page shows. It must be inside `public/`, which the site serves at `/`, so a file at `public/docs/guide/a.png` is `/docs/guide/a.png` in a page. |
| `diagrams` | `diagrams` | The diagram files `<Diagram src>` draws. |
| `baseUrl` | `/docs` | The URL the site gives the pages, as in fumadocs' `loader({ baseUrl })`. Links between pages are checked against it. |

## Opening a project

```sh
npm run studio -- <folder>
```

The folder is read from where npm runs, and defaults to it. The Studio
finds the repository the folder is in: change requests branch the whole
repository, and the paths it shows are paths in there. These docs are
opened with `npm run docs`, which is `npm run studio -- docs`.

:::note
Only the paths are configurable for now. The components the editor knows,
the theme and the editor's stylesheets come with the Studio.
:::
